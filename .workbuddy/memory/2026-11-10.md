# 2026-11-10

## sourceWeb = "data"：接入 pumpfundata 作为代币来源

需求：线路 `sourceWeb` 为 `"data"` 时从 pumpfundata 取 pumpfun 内盘数据，支持与 AVE 相同的
`mcp_min / mcp_max / create_day / create_day_end / category` 筛选，返回结构不变（前端不改）。

### 实测结论（重要）
- 数据源无筛选/排序接口，只有 `/range` + `/download`（逐小时 parquet），无市值字段，市值要自己算。
- 覆盖 2026-02-08 ~ 今天（pump_fun 6347 个文件）。1 credit / 小时文件，30 req/min。
- 真实文件：每小时约 13.6 万行，**ZSTD 压缩**，须装 `hyparquet-compressors`。
- 实测每小时约 1149 个 create / 39 个 bonding_complete / 3517 个活跃 token。
- **计价单位不只有 WSOL**：一小时内有 60+ 种 SPL 代币被当作 lamports_mint。
  未知计价必须标为 `other` 且市值记 0，否则会污染 mcp 筛选。
- 内盘定价必须用 `virtual_*_reserve`；`real_lamports_reserve` 开盘为 0，用它兜底会算出 0 市值。
- 供应量取 create 事件的 `token_total_supply`（raw），不要硬编码 10 亿。

### 实现
- `app/libs/pfd/`：`store.js`(下载/限速/缓存/402)、`parquet.js`(hyparquet 分块读)、
  `indexer.js`(事件聚合+市值)、`aveShape.js`(AVE 字段映射)、`solPrice.js`(SOL/USD 多源竞速)、
  `manager.js`(单例编排/补齐小时/查询)
- `app/model/pfdToken.js`、`pfdCoverage.js`：token 级索引 + 已入库小时水位
- `app/service/pumpData.js`、`app/controller/pumpData.js`：`getList/warm/status`
- 路由：`POST /v1/pumpdata/{status,warm,tokenList}`
- `executeToken.js` 分发新增 `sourceWeb === "data"`；`config.pumpFunData` 配置块
- 脚本：`scripts/pfd-selftest.js`(合成数据)、`pfd-integration-check.js`(真实 parquet 端到端)、
  `pfd-live-check.js`(连通性/余额)

### 设计取舍
- 小时文件只下一次，磁盘缓存 + Mongo `PfdCoverage` 水位记录，重启不重复扣费。
- 日 credit 预算默认 400，单次补数据上限 48 文件，后台补数据有 60s 冷却。
- 当前小时（未结束）按 `refreshLatestMinutes`（默认 10 分钟）节流重下，换取市值新鲜度。
- 5m/15m/1h 指标来自进程内「最近两小时逐笔缓冲」，回补历史时丢弃过期成交避免内存爆掉。
- 排序用归一化 `mcapUsd` 字段，避免 SOL/USDC 计价混排错乱；筛选仍用当前 SOL 价换算 $or 区间。
- 外盘（pump_out）不能拿内盘末价筛市值（会全筛空），改为取窗口内全部已毕业 token，
  叠 AMM 状态后在内存里筛/排/分页（上限 5000）。
- `holders` 数据源没有，固定 0；`icon` 未实现自动解析（未访问链上 metadata，避免 SSRF）。
- 拿不到 SOL/USD 时默认 `skip` 筛选（`missingSolPrice=empty` 可改为返回空列表）。

### 环境注意
- 本机无法访问 Binance/Jupiter/Coinbase（出口被拦），SOL 价格全部走兜底失败；
  生产如同样受限，需设置 `PFD_SOL_USD`。
- 本机 MongoDB (172.17.0.2) 不可达，未能整机启动 egg 验证，仅做静态装载 + 内存版 Mongo 端到端。

## 第二轮：改为全自动定时采集

用户要求：启动跑一次 + 每天定时跑一次，不需要手动跑命令；SOL/USD 默认 0；
非 SOL 计价不返回；数据都放 MongoDB，本地不管。

- 新增 `app/schedule/pfdIngest.js`：`type: worker` + `cron` + `immediate`，默认每天 03:10。
  开关/时间在 `config.pumpFunData`：`autoIngest / ingestCron / warmDays / dailyMaxFiles / ingestAmm`。
  注意 egg-schedule 的 schedule 文件必须导出带 `schedule` 属性的对象；写成 `(app) => ({...})`
  是可行的，因为 FileLoader 默认 `call: true` 会用 app 调用函数导出。
- **删掉请求路径的下载**：`_scheduleWarm` 已移除，queryList 只读 Mongo。
- `buildTokenQuery` 固定 `quoteKind: "sol"`，去掉 `$or`，非 SOL 计价不再返回。
- `missingSolPrice` 默认改成 `empty`（拿不到 SOL 价格直接返回空列表，避免区间外的币被买入）。
- 新增 `dailyIngest()` + `prune()`（按 warmDays+2 清理 token 和 coverage 水位）。
- 稳态成本 24 credit/天/交易所；首次是 `warmDays*24*交易所数`。warmDays 默认 6，即首次约 288。
- 重启后 5m/15m/1h 指标靠 `_rebuildTail` 重读最近 2 小时文件（缺则补下，最多 2 credit）。
- 校验脚本仍然全绿：`npm run pfd:selftest` / `npm run pfd:integration`。

## 第三轮：SOL/USD 兜底价默认 100

- `config.pumpFunData.solUsdFallback` 默认 100（`PFD_SOL_USD=0` 可关掉兜底，其他值可覆盖）。
- 顺带修掉一个性能坑：原来行情源不通时 `getSolUsd()` 会等满 8 秒超时，导致每 60 秒
  有一个接口请求卡住。改成「有兜底价就立即返回 + 后台异步拉实时价」，现在首调用 50ms。
- `scripts/pfd-live-check.js` 之前没读 config 的兜底价，已修。

## 第四轮：图标与 getBuyTokes 补图

问题：tokenList 返回的 `icon` / `token1_logo_url` 都是空；`getBuyTokes` 也没有 icon。

- `token1_logo_url`：直接拼 `{AVE_LOGO_URL}token_icon/solana/{quoteMint}.png`，只对 WSOL/USDC/USDT 生效。
- 图标来源实测结论：
  - `www.iconaves.com/token_icon/solana/{mint}.png` **只对 AVE 已收录的 token 返回 200**，
    新盘一律 403，不能当通用方案（WSOL 是 200）。
  - `dd.dexscreener.com/ds-data/tokens/solana/{mint}.png` 和 pump.fun 接口在开发机被网络策略拦，未验证。
  - 最终方案：后台请求 metadata `uri` 取 `image`，写回 `PfdToken.icon`。
    `app/libs/pfd/icon.js`：并发 4、每次 tokenList 最多排 40 个、队列上限 200。
    网络失败 1 小时后重试，metadata 确实没图则 7 天后重试（`iconError` 区分）。
- `getBuyTokes` / `checkToken`：`ExecuteToken` 新增 `icon` 字段；checkToken 存图
  （tokenData.icon → 已有记录 → pumpData.getIconMap），getBuyTokes 两个分支都用
  `pumpData.getIconMap()` 补齐，老记录也能显示。
- 新增 `scripts/pfd-icon-check.js`（本地 http 服务模拟 metadata，`npm run pfd:icon`）。

## 第五轮：warmDays 改 30 天 + 缓存清理

- `warmDays` 默认改 30。`dailyMaxFiles` / `dailyCreditBudget` 改为按 warmDays 自动推导
  （`warmDays*24+60` / `warmDays*48+200`），避免「改了窗口忘了放大上限」导致回补被截断。
  注意 config 里曾出现重复的 `dailyCreditBudget` 键覆盖新值，已删。
- 30 天 = 1440 个小时文件，parquet 缓存会占 20GB+，所以新增：
  - `cacheKeepHours`（默认 72）：入库后立刻删更早的 parquet（`store.dropHour`）
  - 断点续传：`_markIngested` 改成每 20 个小时落一次水位，长时间回补崩溃不用重下
- `_init` 加载 tracked 集合时排除 `_id`（30 天约 80 万 token，省内存）。
- 回补顺序仍是从老到新（保证 create 必须先于 swap 入库，否则 token 状态会丢）。
  代价：首次回补约 50 分钟，且最近几天的窗口最后才填满，期间建议先别开线路。
