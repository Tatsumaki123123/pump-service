# 2026-11-17

## 内盘（pump.fun 曲线）支持非 WSOL 池子，默认走 Jupiter

需求由来：pumpfundata 采集侧不过滤非 WSOL 池，但查询侧 `quoteKind:"sol"` 过滤；
交易侧内盘只用 `pfSwap.buy/sell` 直连曲线（SOL 硬编码），非 WSOL 池发不出去。

关键事实：**pump.fun 曲线只有 SOL 计价**（bondingCurveAccount 无 quote 字段），
所谓「内盘非 WSOL」= 该 token 已有 USDC/其它 SPL 计价的 Pump AMM 池。

改动：
- `app/libs/pool.js` 新增 `getPumpPoolsWithQuoteInfo()`：列出 token 全部 Pump AMM 池
  并标 `isNativeQuote`，无 WSOL 池不抛错（区别于 `getPoolsWithPrices` 的 NO_WSOL_PUMP_POOL）。
- `app/service/executeSwap.js#checkToken`：
  - 外盘 routeInfo 增加 `useJup/isNativeQuote/amm`，PoolStore 同步写 pool。
  - 新增内盘分支：`amm === "pump"` 时扫池子，只有非 WSOL 池才判 `useJup`；
    结果做 5 分钟进程内缓存（`pumpQuoteCache`），避免每次 checkToken 都 getProgramAccounts。
  - `ExecuteToken` 落 `useJup` / `quoteMint`；更新时若 routeInfo 为空则不覆盖旧 useJup（宁可继续走 jup）。
- `app/model/executeToken.js` 加 `useJup` / `quoteMint` 字段。
- `app/service/pumpfun.js`：`getJupRouteInfo()` 读标记；买卖两侧 useJup 时走
  `jupSwap.getBuyInstructions/getSellInstructions`，SOL 计价进出；预取报价、带
  lookup table 编译、jup 买入额外 simulate 一次；走 jup 时跳过 Axiom 曲线预计算。
- 新增 `scripts/pumpfun-jup-route-check.js`（7 项离线自检，全通过）。

约定：
- 内盘滑点内部是 bps（`SLIPPAGE_BASIS_POINTS=5000n`），Jupiter 要 0~1 小数，
  一律用 `getWalletSlippageFraction()` 转换；`pumpAMM.js` 那边是小数口径，勿混。
- 支付币默认 SOL；`wallet.buyAmount` 语义不变（SOL 计价）。

## run/pfd-cache 占盘：补全量清理

根因：清理只有 `ensureRange` 里「下完就删」一条路径（`manager.js` 的 dropHour），
**没有全量兜底扫描**。所以改配置前下载的旧文件、崩溃留下的 `.part`、入库失败的 slot
永远清不掉（实测本地留着 8 天前的 `2026-11-09/12.parquet`）。

改动：
- `app/libs/pfd/store.js` 新增 `pruneCache({ keepHours, dryRun, all })`：
  按**数据时间**（目录名 + 小时）判过期，`.part` 按 mtime 留 1 小时余量，
  删完顺手清理空日期目录；`all:true` 全清。
- `app/libs/pfd/manager.js` 新增 `pruneDiskCache()`，在 `dailyIngest` 采集结束后调用，
  结果写进 `lastIngest.cachePruned` 并打日志。
- 新增 `scripts/pfd-cache-prune.js`：不依赖 egg，默认 dry-run，`--apply` 才真删，
  支持 `--keep-hours N` / `--all`。

顺带修掉两个既有问题：
- `fs.rm(dir, {recursive:false})` 对目录报 EISDIR，空目录删不掉 → 改 `fsp.rmdir`。
- `scripts/pfd-integration-check.js` 假模型缺 `findOne`（`_explainEmpty` 直接崩），
  且 `createDay: 5` 写死，缓存文件一过期就假失败 → 改成按缓存小时推算窗口。

容量口径：单小时 parquet 实测约 17MB。`PFD_CACHE_KEEP_HOURS` 默认 72，
即稳态约 3 天 × 24h × 17MB × 2 交易所 ≈ 2.4GB；超过这个量就说明有残留。
设 0 = 不清理（历史残留的常见原因）。
