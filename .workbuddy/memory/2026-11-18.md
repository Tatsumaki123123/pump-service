## 排查：pumpfundata 数据「运行久了就不更新」

结论（按影响排序，均为读码定位）：

1. 采集只有一天一次：`config.ingestCron = "0 10 3 * * *"`，`dailyIngest` 每天 03:10 跑一遍；
   `queryList` 明确不触发下载 → 之后 24h 内 priceQuote / mcapQuote / lastAt 全冻结。
2. 逐笔缓冲 `_tail` 只在 `_ingestSlot`（读 parquet）时填充，`TAIL_RETENTION_MS = 2h`，
   `_rebuildTail` 只在 `_init()` 启动时跑 → 采集结束 2h 后 tail 空，
   5m/15m/1h 成交额、笔数、涨跌幅、latest_time 全部归零/冻结。这是「不更新」最直观的来源。
3. 外盘 `queryList` 候选：`sort({createAt:1}).limit(5000)`（manager.js:707-714）取窗口内**最老**的
   5000 个已毕业 token；graduated 超过 5000 后新币永远进不了列表，看着像彻底卡死。待验证量级。
4. credit 402：`_noCreditsAt` 5min 快速失败 + `ensureRange` 遇 402 直接 break；
   重启后若 coverage 的 hours 已被 prune $pull 掉，会重下整个窗口（warmDays=10 → 240×2 credit）。
5. 小 bug：aveShape.js:150 `volume_u_5m` 用了 `stats.vol15m`；`_tracked` 只增不减。

验证入口：`POST /v1/pumpdata/status`（lastIngest / coverage.missingHours / credits / downloadStats / lastError）。

## 修复实施

- 默认调度改为每小时 05 分执行，仅补齐已结束小时（24 credit/天/交易所）；避免定时任务重复强制下载当前小时。
- `dailyIngest` 每轮重建最近两小时 tail，恢复统计指标更新。
- 当前小时手动 warm 使用 transient 下载，不写入完整小时磁盘缓存，避免未完成数据污染后续小时。
- 外盘先按 pump_amm 最新成交取 5000 个活跃 mint，再匹配 pump_fun 毕业币及创建时间窗口；增加 exchange+lastAt 索引。
- `volume_u_5m` 使用 `vol5m`，加入独立时间窗断言。
